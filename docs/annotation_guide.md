# Инструкция сбора и разметки данных

## 1. Сбор

Допустимые источники:
1. **Реальные сообщения** от добровольцев (пилот, родственники команды) — только с письменного согласия
   владельца. Перед сохранением удалить ИИН, телефоны, номера карт, коды, имена и адреса
   (можно `saqbol.service.privacy.anonymize`, затем проверить вручную).
2. **Реконструкции** по публичным описаниям схем (предупреждения банков, полиции, СМИ). В `source_id` —
   ссылка на описание; текст писать своими словами, не копировать.
3. **Синтетика** — только для заполнения редких схем и с пометкой `synthetic`.

Нельзя: собирать чужую переписку без согласия, выкладывать реальные номера и ссылки, использовать
реальные домены мошенников в открытом репозитории (заменять на `example.com`).

## 2. Разметка

**scam** — сообщение пытается получить деньги, коды, данные карты или документы обманом:
выдаёт себя за другого, создаёт ложную срочность, обещает невозможную выгоду, просит предоплату незнакомцу.

**not_scam** — обычная переписка, служебные уведомления, легальная реклама, а также **предупреждения
о мошенничестве** («банк никогда не просит код») и **уведомления с кодом** («ваш код 1234, никому не сообщайте»).

Трудные случаи:

| Текст | Решение |
|---|---|
| «Ваш код 4821. Никому не сообщайте» | not_scam (уведомление) |
| «Продиктуйте код из SMS» | scam |
| «Мам, кинь 5000, потом объясню» | `disputed` — без контекста нельзя решить |
| Агрессивная реклама со ссылкой | not_scam или `disputed`; спам ≠ мошенничество |
| «Банк предупреждает: не переводите на безопасный счёт» | not_scam |

`scheme`: выбрать один основной тип; если подходят два — тот, где требуется действие
(передать код, перевести деньги).

## 3. Группы шаблонов

Один исходный текст и все его переводы, перефразировки, варианты с другими суммами и именами получают
одну `template_group`. Если сомневаетесь, объединяйте: лишнее объединение безопасно, а лишнее разделение
приводит к утечке и завышает метрики.

## 4. Проверка качества

1. Каждый пример размечают два человека независимо.
2. Совпали → `verified`. Не совпали → `disputed`, решение на общем обсуждении.
3. Считать согласие (Cohen's kappa) на 100 случайных примерах и указывать в отчёте.
4. Новый пример → `pending`, пока не проверен.

## 5. Объём и баланс

Цель — 5 000 `verified`: не менее 35% на казахском, все шесть схем по ≥300 примеров, не менее 1/3
«трудных негативов» (уведомления с кодами, предупреждения банков, легальные объявления).
Следить, чтобы длина сообщений в классах не различалась систематически.
