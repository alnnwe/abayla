# Abayla — технический отчёт

AI-помощник против мошенничества для пожилых пользователей Казахстана (RU/KZ). Дата экспериментов: 10.11.2026.

> **Главное ограничение.** Все эксперименты выполнены на демонстрационном синтетическом наборе (286 текстов,
> написаны автором проекта). Числа ниже показывают, что конвейер работает и модели сравниваются корректно,
> но **не являются оценкой качества на реальных сообщениях**.

## 1. Постановка задачи

**Пользователь**: пожилой человек, получивший подозрительное сообщение, ссылку или звонок.
**Вход**: пересланный текст, ссылка или голосовой пересказ. **Выход**: уровень риска (низкий /
не определён / высокий), обнаруженные признаки и одно действие; при высоком риске — уведомление
подтверждённому близкому.

**Почему ML.** Мошеннические тексты бесконечно перефразируются; правила хрупки к формулировкам и опечаткам,
а классификатор обобщает лексику схем. Правила оставлены как интерпретируемый baseline и как источник
объяснений. LLM не принимает решений — только переформулирует объяснение.

**Цели (проверяются экспериментально, заранее не гарантированы):** recall класса «мошенничество» ≥ 0.90 и
precision ≥ 0.85 при одном пороге; p95 времени ответа на текст < 5 с; понятность ≥ 4/5 (только в будущем пилоте).

## 2. Данные

См. `docs/dataset_card.md`, EDA — `reports/eda/`.

- 286 строк, 141 группа шаблонов; scam 145 / not_scam 141; ru 149, kk 133, mixed 4; пропусков и дубликатов нет.
- 6 спорных/непроверенных примеров исключены → 280 в обучении.
- Разбиение по группам (seed 42): train 197 (95 групп), validation 43 (20 групп, 23 scam), test 40 (20 групп, 19 scam;
  ru 20, kk 19, mixed 1). Пересечения групп нет (тест).
- **«Короткий путь»**: мошеннические тексты длиннее (в среднем 120 против 80 символов); классификатор только по
  длине имеет на test ROC-AUC 0.788.
- Предобработка для TF-IDF: нижний регистр, ё→е, ссылки → `URLTOKEN`, телефоны → `PHONETOKEN`, `*1234` →
  `CARDTOKEN`, числа → `0` (меньше запоминания конкретных сумм и персональных данных).
- Аугментация (эксперимент): одна зашумлённая копия train (нижний регистр, удаление пунктуации, пропуск 3% букв),
  только после разбиения; validation и test идентичны (проверено `cmp`).

## 3. Методы

| № | Модель | Суть | Параметры |
|---|---|---|---|
| 1 | Правила | взвешенная сумма 17 признаков (просьба кода с учётом отрицаний, данные карты, «безопасный счёт», удалённый доступ, срочность, угрозы, подозрительный URL …), сигмоида | веса заданы вручную, bias 2.0, не обучается |
| 2 | TF-IDF word + LR | слова 1–2-граммы | C=4, class_weight=balanced, sublinear_tf |
| 3 | TF-IDF word+char + LR | + символьные 2–5-граммы (char_wb) | то же |
| 3a | то же + аугментация | см. выше | то же |
| 4 | XLM-RoBERTa base | дообучение классификатора, 2 класса | 4 эпохи, lr 3e-5, batch 8, max_len 128, warmup 10%, AdamW wd 0.01; **эмбеддинги заморожены** (85.6 млн обучаемых из 278 млн) из-за 3.9 ГБ RAM; выбрана лучшая эпоха по PR-AUC на validation |

Все модели реализуют один интерфейс `ScamClassifier.predict_scores()`; бот переключается переменной
`ABAYLA_MODEL_DIR` без изменения кода (проверено: `ABAYLA_MODEL_DIR=artifacts/models/xlmr python -m abayla.cli scenarios` → 10/10).

**Пороги** выбираются только на validation: `binary` — максимальная precision при recall ≥ 0.90;
`low` — наибольший порог с recall ≥ 0.98; `high` — наименьший порог ≥ binary с precision ≥ 0.95.
Все пороги помечены как **предварительные** (в validation 23 мошеннических примера).
Score — некалиброванная оценка, не вероятность.

**Политика сервиса** поверх модели: сильный признак (просьба кода/данных карты/ИИН, «безопасный счёт»,
удалённый доступ) не допускает ответ «низкий риск» → «не определён»; короткий текст (< 8 слов) с признаком риска →
«не определён» и один уточняющий вопрос.

**Обучение XLM-R** (CPU, 1 ядро): ~55 с на эпоху, всего 313.9 с (первая эпоха шла параллельно с тестами; без нагрузки — около 250 с).

| Эпоха | train loss | val PR-AUC |
|---|---|---|
| 1 | 0.654 | 0.680 |
| 2 | 0.528 | 0.912 |
| 3 | 0.205 | **0.975** (выбрана) |
| 4 | 0.067 | 0.965 |

## 4. Результаты на test (один и тот же test для всех моделей)

Оборудование: Linux x86_64, 1 CPU, 3.9 ГБ RAM, без GPU, Python 3.12.3; scikit-learn 1.9.1, torch 2.15.0+cpu,
transformers 5.22.2. 95% ДИ — бутстрэп по группам шаблонов (2000 повторов).

| Модель | Порог | Precision | Recall | F1 | PR-AUC | ROC-AUC | 95% ДИ recall | 95% ДИ precision | Обе цели |
|---|---|---|---|---|---|---|---|---|---|
| Правила | 0.266 | 0.889 | 0.842 | 0.865 | 0.921 | 0.921 | [0.60; 1.00] | [0.64; 1.00] | нет |
| TF-IDF word | 0.590 | 0.739 | 0.895 | 0.810 | 0.698 | 0.810 | [0.75; 1.00] | [0.48; 0.95] | нет |
| TF-IDF word+char | 0.539 | 0.680 | 0.895 | 0.773 | 0.933 | 0.922 | [0.75; 1.00] | [0.41; 0.92] | нет |
| TF-IDF word+char + аугм. | 0.619 | 0.739 | 0.895 | 0.810 | 0.921 | 0.912 | [0.75; 1.00] | [0.48; 0.95] | нет |
| XLM-R (заморож. эмб.) | 0.036 | 0.720 | 0.947 | 0.818 | 0.945 | 0.940 | [0.83; 1.00] | [0.46; 0.93] | нет |

Матрицы ошибок (TN FP / FN TP): правила 19 2 / 3 16; word 15 6 / 2 17; word+char 13 8 / 2 17;
word+char+аугм. 15 6 / 2 17; XLM-R 14 7 / 1 18. Графики: `reports/figures/`.

**Цели precision ≥ 0.85 и recall ≥ 0.90 одновременно не достигнуты ни одной моделью.**
XLM-R выполнил цель по recall (18/19), но не по precision. Правила ближе всех по precision, но их оценка
оптимистична (см. §5). При n=19 разница в один пример меняет recall на 0.05, а доверительные интервалы
всех моделей перекрываются: **статистически значимого победителя на таком test нет**.

**Задержка** (`Analyzer.analyze`: модель + признаки + URL, без сети Telegram и LLM):

| Модель | Медиана, мс | p95, мс | Загрузка модели, с |
|---|---|---|---|
| Правила | 0.48 | 0.68 | 0.0 |
| TF-IDF word | 1.3 | 1.51 | 0.012 |
| TF-IDF word+char | 2.86 | 3.29 | 0.051 |
| XLM-R | 104.22 | 133.76 | 3.137 |

Между запусками задержка на одном ядре колеблется (в предыдущем запуске медиана XLM-R была 84 мс). Цель p95 < 5 с выполнена для всех моделей **в этой области измерения**. Полное время ответа в Telegram
(сеть, а при включении — LLM с тайм-аутом 4 с) не измерялось. Распознавание голоса — отдельно: 0.70 с на 3 с
синтетического аудио (Whisper tiny, CPU); на реальной речи и модели `small` не измерялось.

**Три уровня риска** (TF-IDF word+char, модель по умолчанию): scam → low 2, uncertain 0, high 17;
not_scam → low 13, uncertain 4, high 4. У XLM-R зона «не определён» очень широкая (пороги 0.015–0.70):
not_scam → low 9, uncertain 10, high 2. Политика сервиса на этом test уровни не изменила (у пропущенных
мошеннических сообщений нет сильных признаков).

**Learning curve** (TF-IDF word+char, качество на validation, 5 случайных подвыборок групп):
PR-AUC 0.833±0.066 (19 групп) → 0.878 (38) → 0.936 (57) → 0.961 (76) → 0.978 (95). Кривая не вышла на плато —
больше данных должно помогать.

**По языкам** (n мало, выводы предварительные): recall kk 0.78 против ru 1.00 у TF-IDF (по 9 мошеннических
текстов); у XLM-R kk 0.89. Доля ложных тревог у TF-IDF word+char: kk 0.40 (n=10), ru 0.36 (n=11).

**Синтетика vs реальные данные:** не выполнено — реальных сообщений в наборе нет.
**Аугментация:** у TF-IDF word+char уменьшила FP с 8 до 6 при том же recall; на test такого размера это в пределах шума.

## 5. Анализ ошибок

Файлы: `reports/errors/errors_<модель>.csv` (текст, схема, язык, score, уровень, найденные признаки).

1. **Ложные тревоги на легальных банковских уведомлениях** («Перевод от Сауле К. 15 000 тенге зачислен на
   карту *1234», «покупка 3 450 тенге») — у всех ML-моделей. Топ-признаки TF-IDF класса scam: `URLTOKEN`,
   «тенге», «0 тенге», «0 0», «үшін», «срочно». Модель выучила «упоминание суммы ⇒ мошенничество».
2. **Пропуск казахского «родственника в беде»** («Апа, тез ақша аударшы, мені тонап кетті…») — пропускают все три
   ML-модели. Один из топ-признаков легального класса — «апа»: в обучающих данных много обычных семейных сообщений
   с этим обращением. Ложная корреляция из состава набора. При этом признаки правил нашли просьбу перевода,
   беду и срочность — но они не «сильные», и политика сервиса уровень не повысила.
3. **Финансовая пирамида «пригласи трёх друзей»** — пропущена правилами в обоих языках и TF-IDF на казахском;
   XLM-R распознал. Схема «рекрутинга» слабо представлена в train.
4. **Антифрод-предупреждения банков** («банк никогда не просит код…») — XLM-R даёт score 0.95–0.98: путает тему
   «о мошенничестве» с намерением. Правила с учётом отрицаний здесь срабатывают правильно, но признак
   «отправитель — банк/полиция» всё равно даёт ложную тревогу из-за слишком низкого порога правил (0.266).
5. **Легальные объявления** («продаю коляску, оплата при встрече») — FP у TF-IDF из-за лексики схемы «объявления».

**Сильные случаи:** просьбы кода и данных карты, «безопасный счёт», фишинговые ссылки, имитация банка/полиции —
recall 1.0 у всех ML-моделей на test (n=4 в каждой из этих схем).

**Почему оценка правил оптимистична:** регулярные выражения писал тот же человек, что и все тексты набора,
включая test. Это не независимая проверка правил.

## 6. Что нужно для достоверной оценки

1. Реальные обезличенные сообщения с согласием владельцев; основной test — только независимые реальные сообщения.
2. Разметка двумя людьми, kappa, ≥ 5 000 `verified`, выравнивание длины между классами, больше казахских текстов
   и «трудных негативов» (банковские уведомления с суммами, семейные просьбы о деньгах).
3. Пороги на validation с ≥ 100 мошенническими примерами; калибровка score (Platt/isotonic).
4. Выбор модели для бота — на validation или новом test, не на этом.
5. Пилот 20–30 пользователей (`docs/pilot_study_template.md`) для понятности и реальной задержки.

## 7. Воспроизведение

```bash
pip install -r requirements-dev.txt
python -m abayla.training.train                    # данные, разбиение, 3 baseline, пороги на val
python -m abayla.training.train --models tfidf_wordchar --augment --splits artifacts/splits_aug --out artifacts/models_aug
pip install -r requirements-ml.txt --extra-index-url https://download.pytorch.org/whl/cpu
python -m abayla.training.train_transformer --epochs 4
python -m abayla.evaluation.evaluate --extra-models artifacts/models_aug/tfidf_wordchar
```
Сид 42 фиксирован; параметры, версия данных (`abayla_demo_v1@c3abdde2ae2a42d2`), время обучения и оборудование
записаны в `artifacts/models/*/meta.json`. TF-IDF и правила детерминированы; результаты XLM-R на CPU могут
незначительно отличаться между машинами.
