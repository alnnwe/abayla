# Сценарий живой демонстрации (5 минут)

Подготовка до защиты (не в эфире): `make train`, `make test`; бот запущен (`make bot`), на телефоне два
Telegram-аккаунта: «бабушка» и «внучка»; `LLM_ENABLED=0` (демо не должно зависеть от сети и ключа).
Запасной вариант без Telegram: `python -m abayla.cli repl` в терминале.

| Время | Действие | Что сказать |
|---|---|---|
| 0:00–0:30 | «Бабушка»: /start → «Қазақша» → показать меню, затем /language → «Русский» | Интерфейс на двух языках, выбор сохраняется в SQLite |
| 0:30–1:30 | Переслать «Ваш код входа: 4821. Никому его не сообщайте.», затем «Продиктуйте код из SMS, иначе карту заблокируют.» | Одинаковые слова «код», противоположные ответы. Признаки учитывают отрицание. Низкий риск не означает «безопасно» |
| 1:30–2:30 | «Подключить близкого» → «Да, разрешаю» → ссылку открыть с аккаунта «внучки» → «Согласна» → у «бабушки» «Подтвердить» | Согласие обеих сторон, ссылка одноразовая на 30 минут, без подтверждения пожилого пользователя связь не активна |
| 2:30–3:15 | «Бабушка» пересылает «Мама, это я, новый номер, попал в аварию, срочно переведи деньги» → у «внучки» приходит уведомление | Родственник получает только уровень риска и просьбу связаться, без текста переписки. Повтор того же сообщения уведомление не дублирует (показать) |
| 3:15–3:45 | Ссылка `http://demobank-verify.example.com/login …` и «скинь 5000» | Ссылки не открываются, анализируется адрес. Короткий текст → один уточняющий вопрос |
| 3:45–4:15 | Нажать «Бот ошибся»; /privacy | Отзыв сохраняется без текста; что хранится и что нет |
| 4:15–4:45 | Терминал: `python -m abayla.cli scenarios`, открыть `reports/results.md` | Сценарии воспроизводимы без Telegram; метрики на демо-test, цели не достигнуты — честно |
| 4:45–5:00 | «Удалить мои данные» → «Удалить» | Данные и привязки удалены |

Если что-то сломалось: переключиться на CLI (`python -m abayla.cli check "..."`) — те же модели и шаблоны.
